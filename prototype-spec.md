# Задача: прототип десктопного приложения для распознавания речи

## Жанр

Стройка с нуля, новый репозиторий. Прототип для запуска **на машине владельца**
(Python, зависимости и модель уже установлены). Упаковка на раздачу другим людям
— НЕ в этой задаче (см. Вне скоупа).

## Что строим

Локальное офлайн-приложение: пользователь выбирает видео/аудиофайл → получает
читаемый пунктуированный текст. Морда — Electron (JS/Node). Движок распознавания
— готовый Python-пайплайн (GigaAM), лежит отдельно, вызывается как подпроцесс.

## Готовый движок (переиспользуем, не переписываем)

Есть рабочий Python-пайплайн `asr_pipeline` (GigaAM v3, проверен на реальных
записях): вход — путь к аудио, выход — сегменты с текстом, таймкодами и
confidence, плюс маркировка неразборчивых мест. Точка входа — `cli.py`.
**Перенеси его в новый репозиторий как есть** (владелец подтвердит откуда).
Не трогай его внутренности, не переписывай на JS.

## Архитектура (чистые модули, без оверинжиниринга)

Три модуля с ясными границами. Никаких абстрактных интерфейсов, фабрик или
«движков на будущее» — движок один, граница между ним и приложением нужна для
читаемости, а не для сменности.

1. **UI** (Electron renderer) — выбрать файл, показать прогресс, показать и
   сохранить результат. Не знает, чем и как распознаётся.
2. **Модуль распознавания** — «путь к файлу -> результат распознавания». Внутри
   запускает Python-пайплайн подпроцессом (образец — как это сделано в старом
   проекте владельца, где Node звал whisper через child_process.spawn), читает
   его вывод, приводит к единому формату результата. Граница чистая: снаружи
   видна функция, не видна кухня Python.
3. **Оркестрация** (Electron main) — тонкий слой: принял файл от UI -> позвал
   модуль распознавания -> вернул результат в UI.

Формат результата задаёт приложение, а не движок: список сегментов
{ текст, начало, конец, confidence }. UI должен корректно показывать результат,
даже если каких-то полей нет.

## Вне скоупа (пока)

- Упаковка в устанавливаемый .exe на чужие машины (Python + модель внутри) —
  отдельная задача, тут не трогаем.
- Структурирование текста в документ (Ollama/шаблоны) — отдельный модуль на
  потом. Сейчас цель — читаемый текст, не оформленный протокол.
- Разделение говорящих (диаризация), серверный режим, база данных, авторизация.

## Поведение

1. Сначала разведка и план: предложи структуру репозитория и порядок шагов,
   дождись подтверждения, потом код.
2. Маленькими шагами, показывай изменения, эскалируй проблемы (особенно стык
   Electron<->Python-подпроцесс — самое рискованное место).
3. Первая рабочая цель — минимальная сквозная цепочка: выбрал файл -> пошёл
   подпроцесс -> вернулся текст -> показался в окне. Всё остальное после неё.
