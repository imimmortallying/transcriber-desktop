# Локальная расшифровка речи

Electron-приложение для локальной офлайн-расшифровки аудио и видео через
GigaAM. Оно помогает превратить машинную транскрипцию в текст
протокольного вида, а не выпускает готовый протокол автоматически и не заменяет
Word или универсальный rich-text editor.

Это новый отдельный проект. Рядом существуют `transcription-mvp` (Whisper — его
не трогаем) и `asr-server` (авторизация и серверная часть — развиваются
отдельно). Этот репозиторий не заменяет их и не является единственным ASR-репо.

Первая рабочая версия уже передана внешнему пользователю для реального
тестирования. Текущее продуктовое состояние, утверждённые направления и
отложенные решения — в `docs/product/module.md`.

## Что реализовано сейчас

- Локальное распознавание аудио и видео через GigaAM.
- Единый документ расшифровки с ручным структурированием, говорящими,
  таймкодами, автосохранением правок, экспортом и сравнением с распознанным
  текстом.
- Настраиваемая папка результатов, список и управление сохранёнными прогонами.
- В установленной Windows-поставке — local/offline Client Update и optional
  Online Acquisition: выбрать подписанный локальный `.asrupdate` либо по явному
  действию проверить/скачать подписанный release; затем подготовить side-by-side
  candidate и после restart применить его с READY/commit либо rollback. Runtime
  при этом не переустанавливается и не изменяется.

Подробности работы документа расшифровки и результатов — в `docs/editor/module.md`; запуска
Python-пайплайна — в `docs/recognition/module.md`; правила и карта документации
- в `docs/README.md`. Lifecycle Client Update и его validation evidence — в
`docs/client-update/module.md` и `docs/client-update/validation.md`;
соответствующие trust boundaries — в `docs/security/module.md`.

## Ключевые решения

- **GigaAM вместо Whisper.** Для этого сценария GigaAM работает примерно в
  соотношении 8:1 и даёт более подходящую пунктуацию.
- **Неуверенность распознавания не скрывается.** В ASR-сегментах сохраняется
  `confidence`: движок не должен галлюцинировать неразборчивую речь, а низкая
  уверенность остаётся честным сигналом для последующей проверки человеком.
- **Документ вместо автодиаризации.** Pyannote проверена на плотных
  допросах с перебиваниями: определяет говорящих неточно и примерно втрое
  увеличивает время обработки. Поэтому говорящих размечает человек в документе.
- **Таймкоды без ложной точности.** GigaAM даёт время сегментов, но не слов;
  документ показывает только начало сегмента, не вычисляя время внутри него.

## Границы текущего этапа

Автоматическая диаризация исключена из пользовательского флоу, хотя CLI-команда
и локальный токен пока остаются в Python-пайплайне. Зависимости диаризации не
входят в `requirements-app.txt`, но `diarization.py` и команда `diarize` пока
попадают в packaged-ресурсы вместе со всем каталогом `pipeline/asr_pipeline`.
Media Review v1 доступен только по явному действию для текущей расшифровки:
он даёт playback и segment-level indication, не меняя autosave/history.
Автопрокрутка, word-level highlighting, final layout и другие interaction
patterns остаются открытыми вопросами в `docs/product/module.md`.

## Устройство

- `src/renderer/` — интерфейс Electron: выбор источника, единый документ
  расшифровки, говорящие, экспорт, автосохранение правок и сравнение с
  распознанным текстом.
- `src/main.js` — оконное приложение и IPC: выбор файлов, список и загрузка
  сохранённых прогонов и связанных с ними проектов, управление папкой сохранённого прогона,
  буфер обмена и сохранение `.txt`.
- `src/preload.js` — минимальный безопасный API renderer-процесса.
- `src/recognition/runRecognition.js` — граница с Python: запускает
  `preprocess` и `asr`, нормализует `{ text, start, end, confidence }` и читает
  сохранённый `segments_asr.json`.
- `pipeline/` — готовый Python-движок; приложение не меняет его внутренности.
- `docs/editor/module.md`, `docs/recognition/module.md`,
  `docs/diarization/module.md` и `docs/packaging/module.md` — сжатый контекст
  решений документа, запуска Python-пайплайна, отключённой диаризации и сборки
  Windows-установщика.

## Первый запуск

Python-окружение создаётся внутри `pipeline/.venv`:

```powershell
cd pipeline
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item config.example.json config.json
```

В `pipeline/config.json` настройте путь к локальному `ffmpeg.exe`. Для
упакованного приложения используется отдельный чистый
`pipeline/config.app.example.json`; его не нужно редактировать конечному
пользователю. Затем установите Node-зависимости и запустите Electron:

```powershell
npm install
npm start
```

Для сборки Windows-установщика см. `docs/packaging/module.md`.

## Файлы результатов

Каждое распознавание сохраняется отдельным прогоном. В приложении можно выбрать
папку результатов, открыть сохранённый прогон и управлять его папкой. Формат
артефактов, настройки путей и поведение списка описаны в
`docs/editor/module.md`.

## Открытые вопросы

- UX-проверка единого документа: убедиться, что ручное структурирование текста
  понятно первым пользователям.
- Конкретный UX media-assisted review: layout, seek/follow-playback, shortcuts,
  video modes и точность highlighting определяются после первых наблюдений.
- Переезд UI на React + Radix: вернуться к решению после первого показа
  реальному пользователю.
- Подсказки и onboarding: определить после первого показа, что действительно
  нужно объяснять пользователю.
- Переименование и удаление говорящих из списка: осознанно вне текущего скоупа.
- Назначение говорящего в начало документа: сейчас сначала нужно создать
  разбиение через Ctrl+Enter.
- Локальное логирование ошибок: сейчас ошибки показываются через alert/status;
  к решению о лог-файле вернуться после первого реального использования.
