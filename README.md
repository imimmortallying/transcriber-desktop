# Локальная расшифровка речи

Electron-приложение для локальной офлайн-расшифровки аудио и видео через
GigaAM. Оно помогает превратить машинную транскрипцию в текст
протокольного вида, а не выпускает готовый протокол автоматически.

Это новый отдельный проект. Рядом существуют `transcription-mvp` (Whisper — его
не трогаем) и `asr-server` (авторизация и серверная часть — развиваются
отдельно). Этот репозиторий не заменяет их и не является единственным ASR-репо.

## Что реализовано сейчас

- Выбор аудио- или видеофайла, подготовка аудио и распознавание GigaAM в
  локальном Python-подпроцессе.
- Выбор папки для новых результатов из интерфейса с показом текущего пути и
  открытием в Проводнике.
- Список сохранённых прогонов и открытие их `segments_asr.json` без повторного распознавания.
- Редактор-документ: ASR-сегменты склеиваются в сплошной текст, который можно
  редактировать и вручную дробить на абзацы и реплики.
- Ручные говорящие: имя вводится в поле интерфейса, а список созданных говорящих
  остаётся на панели для ориентира. Говорящий назначается, меняется или снимается
  локальным выбором у реплики; кликабельный бабл заменяет текстовую подпись имени.
  Обычный Enter обрабатывает браузер, а Ctrl+Enter создаёт реплику: она наследует
  говорящего исходной реплики либо ждёт назначения, если разрыв сделан в обычном
  тексте. Backspace в начале такой реплики сливает её с предыдущим абзацем.
- Таймкод слева у каждого абзаца: это начало первого связанного ASR-сегмента.
- Копирование в буфер и сохранение `.txt` чистого текста без таймкодов, цвета и
  технических меток.
- Явное сохранение ручных правок как проекта рядом с ASR-результатом.
- Сравнение правок с распознанным текстом без чтения файлов и потери ручного
  состояния.

Кнопка «Сохранить проект» записывает ручные правки в
`segments_asr.edits.json` рядом с исходным `segments_asr.json`, не изменяя
машинный ASR-результат. При открытии `segments_asr.json` редактор автоматически
восстанавливает этот проект, если файл правок существует; иначе строит документ
из машинных сегментов. «Сбросить к распознанному» перечитывает исходные сегменты
только в память и не удаляет файл правок.

Когда есть ручные правки, кнопка «Показать распознанное» переключает редактор
в режим сравнения с исходным текстом. Над документом явно показан текущий режим.
Распознанный текст в этом режиме не редактируется, а переключение не изменяет
правки и не обращается к диску. Копирование и сохранение `.txt` используют
именно тот вид, который показан в редакторе.

## Ключевые решения

- **GigaAM вместо Whisper.** Для этого сценария GigaAM работает примерно в
  соотношении 8:1 и даёт более подходящую пунктуацию.
- **Неуверенность распознавания не скрывается.** В ASR-сегментах сохраняется
  `confidence`: движок не должен галлюцинировать неразборчивую речь, а низкая
  уверенность остаётся честным сигналом для последующей проверки человеком.
- **Редактор-документ вместо автодиаризации.** Pyannote проверена на плотных
  допросах с перебиваниями: определяет говорящих неточно и примерно втрое
  увеличивает время обработки. Поэтому говорящих размечает человек в редакторе.
- **Таймкоды без ложной точности.** GigaAM даёт время сегментов, но не слов;
  редактор показывает только начало сегмента, не вычисляя время внутри него.

## Границы текущего этапа

Автоматическая диаризация исключена из пользовательского флоу, хотя CLI-команда
и локальный токен пока остаются в Python-пайплайне. Видео- и аудиоплеера,
перемотки по абзацу и автотемплейтов сейчас нет.

## Устройство

- `src/renderer/` — интерфейс Electron: выбор источника, редактор, говорящие,
  экспорт, сохранение проекта правок и сравнение с распознанным текстом.
- `src/main.js` — оконное приложение и IPC: выбор файлов, список и загрузка
  сохранённых прогонов и связанных с ними проектов, управление папкой сохранённого прогона,
  буфер обмена и сохранение `.txt`.
- `src/preload.js` — минимальный безопасный API renderer-процесса.
- `src/recognition/runRecognition.js` — граница с Python: запускает
  `preprocess` и `asr`, нормализует `{ text, start, end, confidence }` и читает
  сохранённый `segments_asr.json`.
- `pipeline/` — готовый Python-движок; приложение не меняет его внутренности.
- `docs/editor/module.md` и `docs/diarization/module.md` — сжатый контекст
  решений редактора и отключённой диаризации.

## Первый запуск

Python-окружение создаётся внутри `pipeline/.venv`:

```powershell
cd pipeline
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

В `pipeline/config.json` настройте путь к локальному `ffmpeg.exe`. Затем
установите Node-зависимости и запустите Electron:

```powershell
npm install
npm start
```

## Файлы результатов

По умолчанию каждый запуск распознавания создаёт отдельную папку
`data/pipeline/<runId>/` внутри проекта. Папка для новых результатов меняется
в строке «Папка результатов» под выбором источника: там же виден текущий путь
и доступно его открытие в Проводнике. Выбранный путь сохраняется в настройках
текущего пользователя и передаётся и Electron-приложению, и Python-пайплайну;
если пользователь ещё не выбирал папку, используется `data_dir` из
`pipeline/config.json` либо его прежний fallback `../data/pipeline`.

При смене папки существующие прогоны не переносятся и не удаляются. В списке
видны результаты текущей папки; чтобы вернуться к прежним, выберите прежний
путь снова. В каждой папке прогона остаются `normalized.wav` (подготовленная
копия аудио), `vad_segments.json`, `segments_asr.json` и `transcript.txt`; после
явного сохранения проекта там же появляется `segments_asr.edits.json`.

После открытия сохранённого `segments_asr.json` доступны кнопки «Открыть в
папке» и «Удалить прогон». Удаление требует подтверждения и необратимо: оно
удаляет всю папку прогона, включая подготовленное аудио и сохранённые правки.

Для альтернативного Python задайте `ASR_PYTHON` с полным путём к исполняемому
файлу. Чтобы открыть готовый ASR-результат, в приложении выберите «Открыть
сохранённый результат», затем нужный прогон из встроенного списка. В список
попадают только прямые подпапки настроенного `data_dir`, в которых есть
`segments_asr.json`; новые прогоны показаны первыми. Название исходника и дата
берутся из `runId`, а для нестандартного имени папки используются сам `runId` и
дата изменения папки. Рядом с каждым прогоном доступны открытие его папки и
удаление. При открытии соседний `segments_asr.edits.json` будет восстановлен
автоматически.

## Открытые вопросы

- UX-правки редактора: сделать ручное структурирование текста быстрее и
  понятнее.
- Общая защита от потери несохранённых правок: сейчас переключение на другой
  прогон (из списка) или закрытие приложения не проверяет `isProjectDirty` и
  может молча потерять несохранённые изменения — нужна единая проверка на оба
  случая, а не точечная под каждое действие отдельно.
- Привязка видео или аудио к таймкодам абзацев.
- Уборка структуры: вложенный `pipeline/` и спецификации в корне требуют
  отдельного решения.
- Сборка прод-версии: при её настройке явно решить, включать ли
  `pipeline/asr_pipeline/diarization.py` и связанные зависимости, например
  `pyannote`, в упаковку. Диаризация не используется в пользовательском UI
  (см. «Ключевые решения»), а сборка пока не настроена: в `package.json` нет
  `build`, `dist`, `package` или `make`.
