# Задача: три правки редактора (ветка feat/editor)

Модель документа верная (сплошной текст, ремарки работают). Нужно починить ядро,
упростить таймкоды и добавить быстрое открытие результата. Три дела одним заходом.

## 1. Починить работу с говорящими и реплики (критично — ядро)

Причина найдена в консоли: `Error: prompt() is not supported at createSpeaker`
(renderer.js:103). Используется браузерный `prompt()`, которого в Electron нет —
поэтому падает создание говорящего, а вероятно и создание реплики (Ctrl+Enter),
если оно тоже дёргает prompt.

- Убрать ВСЕ вызовы `prompt()` / `alert()` / `confirm()` — в Electron не работают.
- Ввод имени говорящего — через элемент интерфейса (текстовое поле рядом с
  кнопкой «Добавить говорящего», добавление по кнопке или Enter).
- Проверить, что после фикса работают ОБА: добавление/выбор говорящего из списка
  И создание реплики (Ctrl+Enter) с назначением говорящего.
- Проверить консоль на другие ошибки того же рода.

## 2. Упростить таймкоды (убрать ложную точность)

Проверено: giga даёт время только на уровне сегмента (start/end в
segments_asr.json), пословных таймкодов НЕТ. Значит точный расчёт границы
невозможен, а пропорция по позиции курсора — ложная точность и лишняя сложность.

- Убрать пропорциональный расчёт времени точки разрыва по курсору.
- У каждого абзаца показывать просто время НАЧАЛА первого сегмента, попавшего в
  этот абзац (например `00:33`). Без деления диапазона, без вычисления точки
  внутри сегмента.
- Если разрыв попал внутрь одного сегмента — второй абзац берёт время начала того
  же сегмента; точку внутри не вычислять.
- Таймкоды не убирать совсем — они задел под привязку к видео (следующий заход).

## 3. Открыть сохранённый результат без повторного ASR

Сейчас каждый тест требует переждать полное распознавание, хотя результат уже
сохранён на диск (data/pipeline/<run>/segments_asr.json). Нужна кнопка, чтобы
открыть сохранённый результат сразу в редакторе, минуя ASR.

- Кнопка «Открыть сохранённый результат» (рядом с «Распознать»).
- Читает segments_asr.json (дать выбрать файл/прогон или взять последний —
  на твоё усмотрение, проще = лучше) и отдаёт сегменты прямо в редактор, как
  будто распознавание только что прошло.
- Это и ускоряет отладку, и станет реальной функцией: вернуться к прошлой работе
  без пересчёта.
