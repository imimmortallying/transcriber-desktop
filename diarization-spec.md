# Задача: диаризация как второй шаг (ветка feat/diarization)

## Жанр

Добавление модуля в существующий рабочий проект. Работать в ветке
feat/diarization, чтобы легко откатить. Прототип распознавания уже работает —
не ломать его.

## Что добавляем

Разделение говорящих (кто говорит) вторым, отдельным шагом после распознавания.
Движок диаризации — pyannote (модель speaker-diarization-community-1), уже
проверен на реальных записях: на допросе корректно выделяет 2 говорящих.

## Флоу (подтверждён владельцем)

Двухшаговый, диаризация не замедляет основной путь:

1. Пользователь распознаёт файл как сейчас -> быстро получает текст.
2. Отдельная кнопка «Разделить по говорящим» -> запускает диаризацию поверх
   уже готового результата (медленно, несколько минут) -> накладывает роли.
3. UI показывает ОБА результата, переключением: «плоский текст» (как сейчас) и
   «диалог по ролям». Плоский текст не теряется — он остаётся доступен как
   страховка, если диаризация где-то ошиблась.

## Как диаризация сводится с текстом

Распознавание (giga) даёт сегменты с текстом и таймкодами. Диаризация (pyannote)
даёт интервалы «кто когда говорит» (ярлыки SPEAKER_00, SPEAKER_01) без слов.
Сведение — по времени: каждому сегменту текста приписывается тот говорящий, чей
интервал максимально перекрывается с сегментом. Результат пишется в поле
speaker у сегмента (оно уже заложено в AsrSegment как заглушка speaker=null —
диаризация его заполняет).

Ярлыки SPEAKER_00/01 — не имена. Кто из них следователь, модуль не знает и не
должен угадывать. Показывать как есть («Говорящий 1 / Говорящий 2»);
переименование ролей — забота пользователя (или отдельная задача потом).

## Диалог: склейка реплик (подтверждено владельцем)

В режиме диалога подряд идущие сегменты одного говорящего склеиваются в один
блок-реплику. Это убирает рубленость (короткие куски одного человека, разрезанные
VAD по паузам, собираются в связную реплику) как побочный эффект группировки по
говорящему. Плоский текст при этом остаётся несклеенным, как сейчас.

## Важно: чтение аудио через soundfile, НЕ torchcodec

pyannote по умолчанию читает аудио через torchcodec, которого в окружении нет
(проверено — падает с "torchcodec is not available"). НЕ ставить torchcodec
(капризен на Windows). Вместо этого читать WAV через soundfile и передавать
pyannote waveform-словарь: pipeline({"waveform": tensor, "sample_rate": sr}).
Это тот же обход, что уже применён в asr.py для giga — используй его.

Аудио для диаризации — тот же нормализованный моно-16кГц WAV, что готовит
препроцессинг (pyannote его формат принимает напрямую).

## Токен Hugging Face

Модель pyannote gated — для скачивания нужен HF-токен (у владельца есть).
Токен — в локальный конфиг/переменную окружения, НЕ в код и НЕ в git. Модель
качается один раз, дальше работает офлайн (важно для будущей раздачи). Путь к
токену вынести в config, как остальные настройки.

## Архитектура (чистые модули, без оверинжиниринга)

Диаризация — отдельный модуль пайплайна (звук -> кто-когда-говорит) плюс
маленький шаг сведения (наложить роли на сегменты по таймкодам). Не переписывать
распознавание — диаризация дополняет его результат, а не заменяет. Не вводить
абстракций «на будущее»: движок диаризации один.
