# Редактор транскрипции

Редактор — отдельный экран, а не часть первого Quick-сценария. После нового
распознавания пользователь сначала получает текст и явно выбирает «Открыть в
редакторе»; выбор сохранённой расшифровки из «Мои расшифровки» открывает
редактор сразу. Это не меняет модель документа: редактор получает
ASR-сегменты `{ text, start, end, confidence }`, склеивает их текст в один
документ и хранит правки в памяти до явного сохранения проекта.
Сегменты не видны как отдельные блоки: они остаются источником времени для
абзацев. Новый результат приходит из ASR либо из `segments_asr.json`, выбранного
во встроенном списке сохранённых прогонов. Корень списка и новых прогонов
выбирается пользователем в строке «Папка результатов» под выбором источника:
выбранный абсолютный путь хранится в пользовательских Electron-настройках и
передаётся Python-пайплайну параметром `--data-dir`. Если пользователь ещё не
менял папку, используется `data_dir` из `pipeline/config.json` или fallback
`../data/pipeline` относительно `pipeline/`. В список попадают только прямые
подпапки текущего корня, содержащие `segments_asr.json`; новые прогоны идут
первыми. При открытии редактор ищет рядом
`segments_asr.edits.json`: если он есть, восстанавливает ручные правки; если
нет — строит документ из валидного массива ASR-сегментов.

По умолчанию каждый прогон хранится в отдельной папке
`data/pipeline/<runId>/`; после смены корня он хранится в
`<выбранная папка>/<runId>/`. Старые прогоны не переносятся и становятся снова
доступны через список только после возврата прежней папки. Рядом с
`segments_asr.json` лежат `normalized.wav`, `vad_segments.json` и
`transcript.txt`, а после сохранения проекта — `segments_asr.edits.json`.
Название исходника и дата в списке извлекаются из формата runId
`<unix-время>-<имя-исходника>-<uuid>`; при нестандартном runId отображаются его
значение и дата изменения папки. У каждой записи списка есть действия «Открыть
в папке» и «Удалить»; удаление требует подтверждения, необратимо удаляет всю
папку вместе с подготовленным аудио и правками и сразу обновляет список. Уже
открытый сохранённый результат также показывает «Открыть в папке» и «Удалить
прогон» в общей панели. Удаление из этой панели сбрасывает редактор в пустое
состояние. Если файл или папка уже удалены вручную, действие сообщает об
ошибке в статусе и не меняет открытый документ.

Документ состоит из абзацев `text` и `replica`. У `text` `speakerId` равен
`null`, а `replica` ссылается на ручного говорящего с произвольным именем; цвет
применяется только к подписи имени. Инструменты говорящих не занимают основной
экран: их открывает явная кнопка «Говорящие». Тогда имя вводится в поле общей
панели и добавляется кнопкой или Enter; рядом остаётся список созданных
говорящих для ориентира.

Обычный Enter не перехватывается: перенос остаётся нативной обработкой браузера
в редактируемом блоке. Ctrl+Enter работает, только когда текст есть с обеих
сторон курсора: справа создаётся `replica`; при разрыве `replica` она наследует
`speakerId`, а при разрыве `text` получает `speakerId: null`. Тайминги делятся
вместе с текстом. Локальный кликабельный бабл виден только у `replica`: в нём
говорящий назначается, меняется или снимается. Выбор «Без говорящего» возвращает
абзацу тип `text` и `speakerId: null`; отдельной текстовой подписи имени нет.

Backspace в начале model-абзаца обрабатывается отдельно: он сливает его с
предыдущим абзацем, переносит карту таймингов правой части со сдвигом и ставит
курсор в точку разрыва. Удаления пустых абзацев при потере фокуса нет.

У абзаца есть локальные части карты ASR-сегментов. Редактор показывает только
время начала первого сегмента абзаца: пословных таймкодов GigaAM не даёт,
поэтому время внутри сегмента не вычисляется. При разрыве внутри сегмента обе
части получают время начала этого сегмента. После ручной правки слов границы частей карты
масштабируются по длине абзаца, поэтому время остаётся ориентиром.

## Проект правок

Явная кнопка «Сохранить проект» записывает рядом с исходным ASR-файлом
`segments_asr.edits.json`. Файл содержит `schemaVersion: 1`, массивы
`paragraphs` и `speakers`; у абзаца сохраняются `id`, `type`, `text`,
`speakerId`, `start` и карта `timing`, у говорящего — `id`, `name` и `color`.
Исходный `segments_asr.json` не изменяется. При загрузке проверяются версия,
типы полей, уникальность id, связь реплик с говорящими и границы карты
таймингов; неподдерживаемый или повреждённый файл не подменяется молча сырыми
сегментами. Старые файлы версии 1 с `remark` при открытии мигрируются в `text`,
о чём редактор сообщает в статусе; при следующем явном сохранении в файле остаются
только `text` и `replica`.

После загрузки новых id счётчики продолжаются после максимального сохранённого
id. Цвета говорящих восстанавливаются из файла без пересчёта. «Сбросить к
распознанному» перечитывает только `segments_asr.json` в память и не удаляет
файл правок. Если есть несохранённые изменения, редактор просит подтверждение
перед сбросом, выбором нового файла, запуском нового распознавания или открытием
другого сохранённого прогона. При закрытии приложения main-процесс запрашивает
dirty-состояние у renderer и показывает нативное подтверждение; когда правок нет,
все эти действия выполняются без дополнительного диалога.

## Сравнение с распознанным текстом

Если открыт проект правок или пользователь уже внёс ручное изменение, кнопка
переключает вид между правками и распознанным текстом. Редактор сохраняет
исходные ASR-сегменты в памяти и заново строит из них временный вид через ту же
логику, что использует для обычной загрузки. Этот вид не редактируется, не
заменяет `paragraphs` и `speakers`, не меняет dirty-флаг и не читает файлы.
Над документом всегда указан текущий режим. Копирование и экспорт `.txt`
используют показанный вид, а «Сохранить проект» всегда записывает правки
редактора, даже когда открыт распознанный текст.

Копирование и сохранение `.txt` используют одно чистое представление: реплика
выводится как `Имя: текст`, остальные абзацы — только своим текстом. Таймкоды,
цвет и технические идентификаторы остаются только в интерфейсе.
Копирование вызывается маленькой иконкой рядом с заголовком «Текст» и сообщает
об успешном результате или ошибке через общий статус; оно копирует именно
видимое представление — распознанный текст либо правки.

## Открытые технические вопросы

Autosave рассматривается как важное направление надёжности пользовательской
работы, но пока не реализован: правки сохраняются только по явному действию.
Сложная логика модели редактора также должна получить лучшее тестовое покрытие.
